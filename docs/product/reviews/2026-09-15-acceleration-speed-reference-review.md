# 加速与保速：速度参考曲线审查

状态：以下为批准前的审查记录。用户随后批准实施，共享速度曲线现已落地；最新合同见[实施计划](../plans/2026-09-15-shared-speed-profile-and-full-audit.md)，验证与完整审查见[本轮结果](2026-09-15-shared-speed-and-audit-verification.md)。下文“现有/必须修改”指批准前状态。

## 现状与问题

`scn001_v3.json` 的 A-S2-05 在 acceleration 阶段检查高度、横向位置和航向；`speed_hold_airspeed_mps` 仅适用 hold/hold_end，`speed_hold_duration_s` 仅在 hold_end 提供。因而当前确实没有逐帧评价加速空速过程。一个时长值不能说明加速节奏、超调或稳定到目标的过程。

## 已核对的权威内容

- [FAA-S-ACS-17，AP.II.E Air Taxi，印刷 p14 / PDF p19](https://www.faa.gov/training_testing/testing/acs/atp_pl_acs_17.pdf#page=19)：S3 选择安全空速/高度；S4 指定高度保持；S5 指定空速 ±10 kt、高度 ±10 ft 和航迹保持；S6 在不同风况下点到点空中滑行；S7 全过程保持运行限制。当前 item 的来源正是此文件。其 ±10 kt 不能直接称为项目加速段逐秒曲线的容差，更未给 D/A 两层分档。
- [FAA-S-ACS-2，CP.IV.C Air Taxi，印刷 p20–21 / PDF p25–26](https://www.faa.gov/training_testing/testing/acs/commercial_pl_acs_2.pdf#page=25)：同样支持安全速度/高度选择、高度保持、点到点滑行和运行限制；该任务没有 ACS-17 S5 那条指定空速数值，不混称文件。
- [EASA FEM Module 3.3 CPL(H)，p10 Section 2(b)、p17 Section 7](https://www.easa.europa.eu/en/downloads/138658/en#page=10)：滑行/悬停滑行要求恰当操纵以控制速度并保持指定地面航迹；总体完成标准关注平顺、准确、持续可控及运行限制。它是直升机评估资料，对通用 eVTOL 仅作适配参考。

上述相关条款没有规定通用的逐秒加速速度曲线、加速秒数或固定保速秒数。参考曲线形状、时间及 D/A 允许量属于项目的场景训练目标；须对应模拟器能力和给学员的任务要求。评价曲线跟踪可补上速度过程，不能仅凭它证明全部操纵平顺性或全部官方条款达标。

## 建议的可讨论合同

1. 将“目标空速与保速”改为“加速与保速速度控制”，用覆盖 acceleration 至 hold 结束的单条参考曲线取代固定保速目标和单点保速时长。其他高度、航迹/航向检查保留。
2. 输入仍按 item 内真实帧组织，每帧含已标明 phase_id、真实 timestamp_s 和原始空速。系统不识别开始加速，也不从操纵数据另找事件边界。
3. t0 为输入已标记 acceleration 的首帧时间；每帧相对时刻 tau=timestamp_s-t0。整个加速/保速共用一个 t0，进入 hold 不重新归零，不删除间隔或拉伸时间。此起点定义不评价首帧之前的反应延迟。
4. 配置保存按时间严格递增的参考节点 (elapsed_s, expected_speed)，起点0。节点之间线性插值参考目标，仅在真实输入帧上评价；不插值观测数据，不取最接近的参考时间节点，不在曲线别处找最相近的速度。
5. deviation=实际速度-插值目标。沿用带符号的 D/A 下侧/上侧允许量；先 D 后 A，其余有效观测为 U，D/A=>Pass，U=>Fail。曲线斜坡覆盖加速，平台覆盖保速；每个输入帧提供证据，参考节点不算额外观测。
6. 明确完整性：参考曲线需覆盖整个被评分时间；真实输入也需覆盖规定任务末端，不能只传开头即通过。参考越界、尾段缺测/覆盖不足应明确报无法完整评估，不当作有效 U 或补好表现。具体结束时刻的采样允许差另定义，不默认为秒级时间宽容。
7. 速度量沿用当前空速口径。若要改为地速或沿航线速度，输入、参考目标、单位和标准适配需一起明确，不能混用。

计算例仅演示插值、不推荐飞行数值：参考 (0s,0m/s)、(2s,4m/s)、(6s,10m/s)、(16s,10m/s)。加速首帧28.3s，实际帧30.7s，则 tau=2.4s，参考速度4.6m/s；若实际5.0m/s，则偏差+0.4m/s，随后按用户填写的容差判档。

## 现有实现可复用与必须修改处

- `frame_calculator.py::_profile_expected` 已有线性插值、闭端点和拒绝外推，可以复用。现有 `phase_profile` 在每个 phase 首帧单独归零，不能直接满足共同 acceleration 起点；需新增明确的共享起点参考模式。
- 现有参数编辑器以 phase 分开编辑节点，需改成一张覆盖加速/保速的共同曲线编辑表。已有原值图使用逐帧 expected，能承接动态期望；报告要清楚表达原始时间与相对时间。
- 现有演示生成器的加速阶段未导出空速，内部 current_speed 先设为保速目标。未来扩大适用阶段时必须同步生成真实的合成加速曲线，不能直接把当前值暴露为加速观察。
- 现有空中滑行阶段没有配置 required_duration_s，现有插值仅拦截参考越界，未自动验证参考尾段的数据覆盖。移除时长字段时必须同时补齐完整性合同。
- 当前三个检查点可以继续保留；若只是替换第一个检查点内的观察方法，不必新增 item 或改变模型结构。但旧 CPT 针对新的证据含义仍需注明未标定，不能把原演示分当可直接横向比较的已验证能力分。
